# Hermes Touch v0.8.3 – lokale NS4168-Lautsprecherausgabe (Kandidat)

**Hardwarestand bestätigt (11.10.2026):** Der Pi hat den kombinierten v0.8.3-Mikrofon-/Lautsprecher-Kandidaten mit **130/130 Tests und `CONNECTED COMPILE OK`** geprüft; anschließend wurde v0.8.3 manuell geflasht. Der Anwender bestätigte einen **hörbaren NS4168-Testton**, `SPK: OK 1`, weiter reagierenden Mikrofonpegel und `TLS OK` auf echter Hardware. Die PCM-/PSRAM-Anzeige der v0.8.3 funktionierte ebenfalls. **Neue UI-Arbeiten ab v0.8.4 sind hier nicht enthalten**; der neue Kandidat ist [Landscape mit eigenem SPRACHE-Tab](V0.8.4-LANDSCAPE-VOICE.md) und muss separat auf dem Pi gebaut werden.

## Herstellerreferenz

Referenz: [OpenNextion ONX3248G035 ESP-Arduino / 07_microphone_test](https://github.com/OpenNextion/OpenNextion-SKU-ONX3248G035/blob/5b4778c3503097f6de409536679c41a8175bfe08/Example%20Programs/ESP-Arduino/07_microphone_test/07_microphone_test.ino).

Die offizielle Arduino-Vorlage nutzt neben PDM RX (GPIO19/20) einen **NS4168-Verstärker am I²S1-TX**:
- **GPIO14:** I²S BCLK
- **GPIO15:** I²S DATA/DOUT
- **GPIO16:** I²S WS/LRCLK
- **PCF8574-Adresse 0x38, Pin P0:** `I2S_CTRL`, Verstärker aktiv bei HIGH, stumm bei LOW.
- **PCF8574-Pin P6:** LCD_RESET (unabhängig von P0).
- **16 kHz, 16 Bit, Mono**, I²S Standard MSB.
- Das Board beziehungsweise die angeschlossene Lautsprechereinheit muss die NS4168-Ausgangsstufe tatsächlich besitzen; vorhandene Pins allein beweisen nicht, dass ein Lautsprecher montiert ist.

Die aktuelle PDM-Eingangsbibliothek `ESP_I2S` verwendet `I2S_NUM_AUTO`. **Das neue I²S1-TX wird deshalb erst gestartet, wenn PDM RX seinen Initialisierungszustand gemeldet hat.** So kann das Mikrofon zunächst den geeigneten Controller belegen, bevor die Ausgabe I²S1 beansprucht.

## Sicherheitsarchitektur

- Der Lautsprecher ist durch `HT_SPEAKER_TEST_ENABLED=0` **standardmäßig AUS** und wird nur durch eine **bewusste Änderung der privaten Config.h** aktiviert; unabhängig vom Mikrofon-Schalter.
- Es gibt **keine Audioeingabe aus HTTPS/Hermes, keine TTS-Engine, keine Speicherung, keine Wiedergabe der PTT-Puffer**, keine Chat-Aktivierung.
- Bei einer Betätigung der im CHAT-Diagnosebereich nach unten scrollbar platzierten Taste **TESTTON** wird genau ein **250-ms-Sinuston (660 Hz)** mit niedrigem digitalen Pegel ausgegeben. Die Lautstärke hängt zusätzlich von der Beschaltung des NS4168 und vom Lautsprecher ab.
- Der Lautsprecher-Task übernimmt I²S1-TX, erzeugt PCM in einem **256-Sample-Stackpuffer** und schreibt mit Zeitlimits in I²S. Der FreeRTOS-Task greift **niemals auf LVGL, `Wire` oder PCF8574** zu. Ein gedoppelter Tastendruck wird abgewiesen; es gibt keine Warteschlange.
- Die PCF8574-Ausgänge werden im Hauptthread über einen **8-Bit-Schattenwert** geschaltet, damit NS4168 P0 den LCD-Reset P6 nicht unbeabsichtigt beeinflusst. Der Verstärker wird beim Start mit **P0 LOW** deaktiviert. Vor dem Ton gibt der Hauptthread den Verstärker frei; nach dem Ton, bei Fehlern und im Ruhezustand wird er erneut deaktiviert.
- **Keine PTT-Rohdaten** werden an den Lautsprecher weitergegeben. Kein Mikrofonmonitoring, das Rückkopplung verursacht.
- Die bestehende HTTPS-Verbindung bleibt **lokal CA-validiert**, der ESP32 darf weiterhin nur `GET /v1/status`. **CHAT / SENDEN / Agent-Befehle** bleiben deaktiviert.

## Separat in der privaten Konfiguration aktivieren

In `firmware/HermesTouch/Config.h` (lokal und `gitignore`-geschützt) genau **einmal** ergänzen:

```c
#define HT_SPEAKER_TEST_ENABLED 1
```

Wenn die Definition schon existiert, statt zu duplizieren `0` auf `1` ändern. **Niemals die gesamte Config.h hier posten!** Sie enthält WLAN-Passwort und ein HTTPS-Geräte-Token. Die ebenfalls vorhandene Option `HT_MIC_TEST_ENABLED=1` kann aktiviert bleiben, damit Mikrofon-Diagnose und Lautsprecher-Test parallel geprüft werden.

## Raspberry Pi: Tests und neuer Build (noch kein Flash)

```bash
cd ~/Projekte/OpenNextion_Hermes_Dashboard
git status --short
git pull --ff-only
python3 -m unittest discover -s tests -q
# Nach dem Eintragen von HT_SPEAKER_TEST_ENABLED 1 in der privaten Config.h:
bash scripts/pi/firmware-build-connected.sh
```

**130 Python-Tests erwartet** (118 zuvor bestätigt + 12 neue Speaker-Verträge). Beim Connected-Build müssen **beide Schalter `HT_MIC_TEST_ENABLED=1` und `HT_SPEAKER_TEST_ENABLED=1`** in der privaten Konfiguration wirksam sein, sonst wird der Lautsprecher-Code zwar quellbasiert getestet, aber **nicht mitkompiliert**. Der Build sollte `CONNECTED COMPILE OK` und `NOTHING FLASHED` ausgeben.

Zur schadlosen Prüfung der Schalter (keine Geheimnisse):

```bash
grep -E '^#define HT_(MIC|SPEAKER)_TEST_ENABLED [01]$' firmware/HermesTouch/Config.h
```

**Keine automatische Firmwareübertragung.** Vor einem späteren manuellen Flash `bash scripts/pi/tls-smoke.sh`, Portzuordnung `ls -l /dev/serial/by-id/`, Firmware-Fingerprint und die neue Build-Ausgabe prüfen. Fehlerprotokolle nur als relevante Fehlerzeilen bereitstellen; weder `Config.h` noch `LocalCa.h` oder private Tokens ausgeben.

## Erster Hardwaretest nach separater Freigabe

1. Nach manuellem, bestätigungspflichtigem Flash im CHAT-Reiter **im oberen Diagnosefeld nach unten scrollen**, bis **TESTTON** und `SPK: BEREIT` sichtbar sind.
2. Die Taste **einmal** drücken. Erwartet: kurzer leiser Signalton (250 ms), danach `SPK: OK 1`. Bei `SPK: FEHLER` nicht wiederholt drücken, sondern I²S/PCF8574 prüfen.
3. Kontrollieren, dass die **Mikrofonpegelanzeige weiter reagiert** und PTT-Aufnahmen weiterhin nach vier Sekunden automatisch verworfen werden.
4. Nach einigen Testtönen STATUS auf `TLS OK` und SYSTEM auf Heap-/Stack-/PSRAM-Stabilität prüfen. Speziell den LCD-Reset und den PCF8574-Verstärker im Auge behalten.
5. Bei fehlendem Ton trotz `SPK: OK`: Lautsprecheranschluss, NS4168-Beschaltung und Hardwarepegel prüfen. `SPK: OK` belegt nur eine erfolgreiche I²S-Schreibroutine – **keinen akustisch nachgewiesenen Ton**.

Das ist **nur der Audioausgabe-Hardwarepfad**, keine Sprachausgabe von Hermes. Eine spätere sichere TTS-Wiedergabe auf dem ESP32 benötigt eine separat geplante Audioquelle, authentifizierte Abrufe und strikte Rechte-/Größenbeschränkungen.
