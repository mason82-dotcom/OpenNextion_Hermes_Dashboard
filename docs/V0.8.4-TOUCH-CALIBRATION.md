# Hermes Touch v0.8.4 – CST826-Touchversatz im Landscape diagnostizieren

## Befund (11.10.2026)

Auf der echten ONX3248G035-Hardware ist **v0.8.4 mit 480×320-Landscape** manuell geflasht worden. Der Nutzer meldet: **„Toucheingabe ist diagonal versetzt“**. Der Pi-Build und **141/141 automatisierte Tests** waren vorher erfolgreich. Das beweist die tatsächliche CST826-Achsenorientierung ausdrücklich **nicht**. Die zuvor verwendete Abbildung `(479 - rawY, rawX)` war nur eine mathematisch getestete Annahme.

**Keinesfalls auf Verdacht die Displayrotation oder Pinbelegung ändern.** v0.8.3 war in Portrait mit funktionierender Toucheingabe, PDM-Mikrofon, hörbarem NS4168-Testton und `TLS OK` auf Hardware bestätigt.

## Zusätzliche USB-only-Diagnose

Die neuen Quellcodedateien unterstützen acht **volatile** Profile in `LandscapeTouch.h`. Der Standard bleibt vorerst Profil 0 (bisherige Transformationsannahme). Zur sicheren Diagnose nur lokal in privater `firmware/HermesTouch/Config.h` ergänzen:

```c
#define HT_TOUCH_CALIBRATION_ENABLED 1
```

Nur genau eine Definition verwenden. **Nie Config.h, LocalCa.h, WLAN-Passwörter oder Tokens ins Chatprotokoll kopieren.** Das Flag ist ohne explizite private Aktivierung **AUS**. Es werden **nur lokale Touch-Koordinaten** mit 115200 Baud auf USB-Serial geschrieben. Keine Speicherung, kein MQTT, kein neuer HTTPS-Endpunkt, keine Änderung der Hermes-Schreibrechte, keine TTS-/Audioübertragung.

### Pi: Test, Connected-Build, manuelles Flash

```bash
cd ~/Projekte/OpenNextion_Hermes_Dashboard
git status --short
git pull --ff-only
python3 -m unittest discover -s tests -q
grep -E '^#define HT_(MIC|SPEAKER|TOUCH_CALIBRATION)_TEST_ENABLED [01]$|^#define HT_TOUCH_CALIBRATION_ENABLED [01]$' \
  firmware/HermesTouch/Config.h
bash scripts/pi/firmware-build-connected.sh
bash scripts/pi/tls-smoke.sh
ls -l /dev/serial/by-id/
```

**146 Tests erwartet** (bisher 141 + 5 neue), darunter real ausgeführte Host-C++-Tests aller Profile. Ein erfolgreicher Build meldet `CONNECTED COMPILE OK` und `NOTHING FLASHED`. Wenn die Tests oder der Build fehlschlagen, **nicht flashen**. Die zuvor erstellte Binärdatei ist wegen neuer Quellen nicht mehr aktuell.

Ein späterer manueller Upload darf erst nach dieser Prüfung und ausdrücklich gewollter Bestätigung erfolgen:

```bash
bash scripts/pi/firmware-upload-connected.sh \
  /dev/serial/by-id/usb-1a86_USB_Serial-if00-port0
```

Das Upload-Skript fragt nach `FLASH-HERMES-TLS`; es **flasht nicht automatisch**.

## Hardwarediagnose über USB

Nach erfolgreichem, bewusst ausgeführtem Upload den Adapter mit dem seriellen Monitor öffnen (kein anderer Serial-Monitor darf gleichzeitig auf die Schnittstelle zugreifen):

```bash
arduino-cli monitor -p /dev/serial/by-id/usb-1a86_USB_Serial-if00-port0 \
  --config baudrate=115200
```

Auf der neuen Landscape-Anzeige steht `TOUCH: PROFIL 0`. Das ist die bislang fehlerhafte Annahme.

1. Mit dem Finger **die Mitte des sichtbaren Tabs STATUS** (links, x etwa 50, y etwa 56) berühren und den gedruckten Eintrag `TOUCH_RAW x=... y=... -> LVGL x=... y=... profile=0` notieren.
2. Dann **die Mitte des sichtbaren Tabs SPRACHE** (rechts, x etwa 430, y etwa 56) berühren und den zweiten Eintrag notieren.
3. Im seriellen Monitor das Kommando `T1` (großes **T** und Ziffer) eingeben und senden. Der Monitor zeigt `TOUCH_PROFILE=1` und die Bildschirmzeile `TOUCH: PROFIL 1`.
4. Falls Touch noch versetzt ist, Profile `T2` bis `T7` nacheinander ausprobieren, bis die sichtbaren Tasten links und rechts **an der berührten Stelle** reagieren.
5. Melden: die **beiden Rohwert-Zeilen**, welcher Modus passt, und ob **STATUS, SPRACHE und der mittlere SYSTEM-Tab** korrekt antippbar sind.

Die Profile berücksichtigen native Portrait-/ bereits Landscape-XY-Achsen mit Achsentausch bzw. Spiegelung. **Bis zu diesem Hardwarebeleg ist kein Modus als richtig bestätigt.** Bei USB-Neustart startet die Diagnose erneut mit Profil 0; das ist beabsichtigt und wird nach Bestätigung dauerhaft (in Quellcode, ohne Speicherung der privaten Config) festgelegt.

## Sicherheit und Grenzen

- Nur die lokale GUI darf die Touch-Abbildung verwenden; Touchdaten gehen nicht in Telemetrie oder über HTTPS. Alle bestehenden `POST`-Verbote bleiben erhalten.
- Um Fehler zu beheben, keine GUI-Buttons mit falscher Touchzuordnung wiederholt betätigen: Auf `SPRACHE` könnten sonst unbeabsichtigt lokale PTT-/Testton-Funktionen getroffen werden. Für die ersten beiden Messungen **nur die beiden Navigationsleisten-Punkte** antippen.
- Eine USB-Änderung des Touch-Profils speichert **nichts** in Flash, EEPROM oder NVS.
- Nach dem Test wieder `HT_TOUCH_CALIBRATION_ENABLED 0` setzen bzw. Definition entfernen und auf Basis des bestätigten Profils den dauerhaften Patch mit neuem Build und Tests erstellen. Kein eigenständiges weiteres Flashen bei unbekanntem Mapping.
