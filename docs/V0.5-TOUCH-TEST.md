# Hermes Touch v0.5 – Vier-Seiten-Displaytest

**Status:** Für das bereits erfolgreich getestete ONX3248G035 implementiert; neuer v0.5-Build/Hardwaretest muss noch auf dem Pi bestätigt werden. Die ursprüngliche v0.4-Testfirmware wurde erfolgreich geflasht; Display, CST826-Touch und 8192 KB PSRAM sind nachgewiesen.

## Ziel

Eine LVGL-Oberfläche mit 4 Touchseiten bei 320 × 480 Pixeln:

| Reiter | Funktion im Offline-Test |
|---|---|
| STATUS | Zeigt echte lokale ESP32-Werte: Heap, PSRAM, Laufzeit und Touch-Aktionen |
| GRAPH | Zeigt **gemessenen freien ESP32-Heap** (KB) als Verlauf mit 24 Messpunkten |
| SYSTEM | Board- und Speicherübersicht, Echtzeit-Touchzähler |
| CHAT | Nur gesperrter Platzhalter; keinerlei Netzwerk-/Hermes-Schreibzugriffe |

**Wichtig:** Ohne `firmware/HermesTouch/Config.h` werden ausdrücklich **keine Pi-Livedaten** angezeigt und kein WLAN initialisiert. Im Diagramm sind keine künstlichen Pi-Messwerte enthalten. Bei gleichmäßigem Heap kann die Kurve recht flach aussehen.

Messung alle 5 Sekunden. `JETZT AKTUALISIEREN` fordert unmittelbar eine neue Messung an. `VERLAUF ZURUECKSETZEN` löscht nur die lokale Display-Kurve. Beide Aktionen sind rein lokal.

## 1. Code aktualisieren und Unit-Tests ausführen

```bash
cd ~/Projekte/OpenNextion_Hermes_Dashboard
git status --short
git pull --ff-only
python3 -m unittest discover -s tests -v
```

Die vollständige Suite enthält nun 12 Bridge-Tests und 6 statische Firmware-Vertragstests, insgesamt 18. Diese Tests prüfen **nicht** die tatsächliche Displaydarstellung und ersetzen keinen ESP32-Compilerlauf.

## 2. Neue Firmware vollständig und sauber bauen

```bash
bash scripts/pi/firmware-build-offline.sh
```

Erst nach `SUCCESS: clean offline firmware compile completed.` fortfahren. Das Skript flasht nicht. Es setzt auf dem Pi die bereits installierten Versionen ESP32-Arduino-Core 3.3.2, LVGL 8.3.11, ArduinoJson 7.4.2 und die OpenNextion-Displaytreiber voraus.

Falls Compiler-/Linkerfehler auftreten: `build/logs/firmware-offline-build.log` enthält die vollständige lokale Ausgabe. Nur die relevanten Fehlermeldungen teilen, keine Zugangsdaten.

## 3. Gerät prüfen und gezielt flashen

Der bereits durch Ab- und Anstecken bestätigte Adapter lautet
`/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0`. Vor dem erneuten Flashen trotzdem erneut prüfen, dass das richtige Gerät angeschlossen ist.

```bash
ls -l /dev/serial/by-id/
bash scripts/pi/firmware-upload-offline.sh \
  /dev/serial/by-id/usb-1a86_USB_Serial-if00-port0
```

Die bestehende Firmware wird ersetzt. Der Upload verlangt die manuelle Eingabe `FLASH-OPENNEXTION`, und er verwendet nur die durch den Build erzeugten Offline-Binärdateien.

## 4. Touch-Testprotokoll

1. **STATUS:** `OFFLINE-DEMO AKTIV`, Heap/PSRAM-Werte sichtbar. `JETZT AKTUALISIEREN` berühren; Touch-Aktionen steigen.
2. **GRAPH:** Nach circa 10–30 Sekunden eine Heap-Messkurve; `VERLAUF ZURUECKSETZEN` testen.
3. **SYSTEM:** `ESP32-S3`, `ST7796U`, `CST826`, `320 x 480` und die 8 MB PSRAM erscheinen. Uptime steigt.
4. **CHAT:** Nur der Hinweis `CHAT IST DEAKTIVIERT`; keine Eingabemaske, kein Senden.
5. **NAVIGATION:** Alle vier Tabs antippen und kontrollieren, ob die Seiten zuverlässig wechseln.

Wenn die Kurve nur eine horizontale Linie zeigt, ist das bei konstantem freien Heap **kein Fehler**. Bei leerem Chart zunächst mehrere 5-Sekunden-Zyklen abwarten; Anzeigeprobleme mit Foto melden.

## Sicherheit

Die Pi-Bridge bleibt unter `127.0.0.1:8765` geschützt und läuft unverändert. **Für v0.5 werden weder WLAN-SSID noch Token benötigt.** Die spätere Live-Daten-Anbindung wird erst nach Festlegung eines verschlüsselten Übertragungswegs aktiviert.
