# Hermes Touch v0.8.1 – lokaler Nextion Dual MIC Board Pegeltest

**Abnahme bestätigt (11.10.2026):** **94/94 Python-Tests**, Connected-Build mit privater HTTPS-Konfiguration und anschließender **manueller Flash auf das ONX3248G035** wurden vom Anwender bestätigt. Im CHAT-Reiter wurden **v0.8.1, TLS OK und ein auf Sprache reagierender relativer Mikrofonpegel** fotografisch überprüft. Das Dual MIC Board ist angeschlossen. Die v0.8.1-Firmware ist die **funktionierende Ausgangsversion** für den anschließenden v0.8.2-PTT-Test; sie darf nicht als Beleg für eine bereits abgenommene PTT-Funktion verstanden werden.

## Hardware und Software

- Board: **OpenNextion ONX3248G035**, ESP32-S3; externes **Nextion Dual MIC Board** am `MIC_PDM`-Anschluss.
- Offizielle Pinbelegung: **CLK GPIO19, DATA GPIO20** (geteilte GPIO-Signale; Kamera/GPIO-Erweiterung parallel nicht verwenden).
- PDM-Empfang: Arduino-ESP32-Core **3.3.2** `ESP_I2S.h`, `I2S_MODE_PDM_RX`, zunächst **16 kHz, 16 Bit, Mono**. Für den ersten Pegeltest muss noch keine stereofone Zuordnung der beiden Mikrofone bestimmt werden.
- `MicLevelWorker.h` enthält einen separaten, mit 4096 Bytes Stack gestarteten FreeRTOS-Task. Er liest jeweils 256 PCM-Samples in einen **temporären lokalen Stackpuffer**, berechnet den relativen RMS-Pegel und verwirft den Puffer unmittelbar.
- An LVGL wird ausschließlich `levelPercent` (0–100), Gültigkeitszeit und Fehlerstatus über einen Mutex übergeben. Abtastung blockiert niemals die LVGL-Hauptschleife. Die Anzeige unter CHAT wird höchstens etwa alle 100 ms erneuert.

**Kein Sprachversand, keine Aufnahme-Datei, kein Audio im Pi/TLS-JSON, keine Transkription, keine Hermes-Schreibbefehle.** Die Chat-Eingabe und der Senden-Knopf bleiben deaktiviert. Das weiße gesperrte Eingabefeld der vorherigen Hardwareaufnahme wird durch ein dunkles, optisch gesperrtes Feld ersetzt.

**Datenschutz:** Ist der Test aktiviert, wird das Mikrofon fortlaufend im RAM für einen relativen Pegel abgetastet, auch wenn ein anderer Reiter geöffnet ist. Es wird **nicht** auf Datei geschrieben und **nicht** übertragen. Das Modul ist in der Firmware standardmäßig vollständig **ausgeschaltet**.

## Schutz durch bewusste lokale Aktivierung

Ohne Schalter ist der Mikrofon-Test `HT_MIC_TEST_ENABLED=0`, der PDM-Treiber wird **nicht** gestartet. Auf CHAT steht **`MIC: AUS (nur lokal)`**.

Nur für einen bewusst gewünschten Hardwaretest in der **lokalen, von Git ignorierten** Datei `firmware/HermesTouch/Config.h` genau eine Definition ergänzen:

```c
#define HT_MIC_TEST_ENABLED 1
```

Die Datei darf **nicht** nach GitHub kopiert werden; sie enthält WLAN-Zugangsdaten und das getrennte TLS-Geräte-Token. Bei bereits vorhandener Definition den Wert stattdessen von `0` auf `1` ändern. Die Änderung erfolgt ausschließlich lokal und beeinflusst erst den **nächsten** manuellen Firmware-Upload. Für einen erneuten Firmware-Build muss diese Konfiguration zur neuen Build-Fingerprint-Prüfung passen.

## Sichere Reihenfolge auf dem Pi

1. Zuerst vor Änderungen an der privaten Konfiguration und ohne Firmware-Upload den neuen Quellstand prüfen:

```bash
cd ~/Projekte/OpenNextion_Hermes_Dashboard
git status --short
git pull --ff-only
python3 -m unittest discover -s tests -v
bash scripts/pi/firmware-build-connected.sh
```

   Erwartet werden **94 Tests** (83 zuvor bestätigt + zwei neue CHAT-Tests + neun Mikrofon-Tests). Der Build ist wie bisher **inkrementell ohne `--clean`** und flasht nichts; in der bestehenden Konfiguration ohne MIC-Schalter wird weiterhin keine Mikrofonhardware initialisiert.

2. Erst wenn die Tests und der Standard-Build erfolgreich sind und der Hardwaretest tatsächlich gewünscht ist, `#define HT_MIC_TEST_ENABLED 1` **privat** in `Config.h` setzen und erneut kompilieren:

```bash
bash scripts/pi/firmware-build-connected.sh
```

3. Vor einem manuellen Flash die weiterhin funktionierenden Pi-Dienste mit `bash scripts/pi/tls-smoke.sh` prüfen und die USB-Gerätezuordnung verifizieren. Dann das bereits vorhandene `firmware-upload-connected.sh` mit dem **verifizierten** `/dev/serial/by-id/... ` verwenden; der Flash erfolgt erst nach interaktiver Eingabe von `FLASH-HERMES-TLS`. **Kein automatischer Upload.**

4. Nach dem Neustart: STATUS zeigt weiter `TLS OK`, CHAT zeigt **`MIC: N % (lokal)`** und einen beweglichen Pegelbalken. Kurz und kontrolliert in das Mikrofon sprechen oder klatschen, ohne Alarmtöne/hohe Schalldrücke. Erwartung: Pegel schwankt bei Geräuschen und sinkt bei Ruhe. Unverändert `0 %` oder `MIC: FEHLER` ist **kein bestandener Mikrofontest**, sondern muss anhand der Audio-/PDM-Konfiguration untersucht werden.

5. SYSTEM erneut prüfen: Heap, größter Block, PSRAM und TLS-Task-Stackreserve. Einige KB zusätzlicher RAM/DMA-Bedarf sind möglich; den bereits bestätigten alten 30-Minuten-Messwert **nicht** als Beleg für v0.8.1 interpretieren. Keine sensiblen Audiodaten oder Konfigurationen veröffentlichen.

Für einen kurzen PTT-Test unter v0.8.2 siehe [v0.8.2 – lokaler PTT-Kandidat mit offizieller OpenNextion-Referenz](V0.8.2-LOCAL-PTT.md). Die hier beschriebenen Schritte dokumentieren die bereits getestete v0.8.1-Funktion und sind **kein erneuter Flash-Auftrag**.

## Grenzen und nächste Entwicklung

Der Pegel ist eine **unkalibrierte relative Anzeige**, kein Schallpegel in dB. Dieser Test bestätigt keine Spracheingabe und keine Stereofunktion. Für eine spätere Push-to-Talk-Funktion benötigen wir ein separates, ausdrücklich autorisiertes Konzept mit lokaler Aktivierung, kurzer Aufnahmezeit, verschlüsseltem Audiotransport, strenger Trennung von Status-Token und Chat-Berechtigungen sowie kontrollierter Spracherkennung auf dem Pi. Bis dahin bleibt Hermes Touch read-only.
